# 日志改造方案

## 目标

日志写入 `/data/logs/l4/`，用 `tail -f` 就能看系统运行情况。数据面不能被磁盘 IO 拖慢，文件不能无限增长。

## 现状

- 所有 `LOG_*` 走 `Logger::log()`（`src/common/logger.cpp`），加 mutex 后 `fprintf(stderr)` + `fflush`，同步写。
- 调用方包括转发核：master lcore（worker 0）同时负责转发和每 10 秒打一次统计，数据面也有 `LOG_RATELIMIT`。
- DPDK 自身日志（EAL、驱动）走 `rte_log`，默认写 stderr。
- 没有处理 SIGHUP，默认动作是终止进程。

如果直接改成同步写文件，磁盘一卡，转发核就跟着卡。

## 设计

### 1. 异步写（只改 logger，`LOG_*` 宏和调用点不动）

- 调用线程照旧格式化整行（时间戳在调用时取），然后放进有界队列就返回，不碰磁盘。
- 单独起一个普通线程 `l4lb-log`（不占 DPDK lcore）当写线程。它在锁内把整个队列 swap 出来，锁外再写。转发核持锁的时间只有一次 push。
- 队列满（默认 8192 条）就丢弃新日志并计数，写线程补一条 `N log messages dropped`。日志永远不会阻塞数据面。
- 刷盘：写线程每 1 秒 `fflush` 一次；批次里有 ERROR/FATAL 时立即刷。
- 退出：`main` 结束前调用 `Logger::shutdown()`，把队列写完再关闭文件。`Logger` 析构时也会调用（覆盖启动失败的早退路径）。
- 写线程启动前（加载配置阶段）和 shutdown 之后，退回原来的同步写 stderr。

### 2. 文件与轮转

```
/data/logs/l4/
  l4lb.log          当前日志
  l4lb.log.1 ~ .N   旧文件，数字越大越旧
```

- 内置按大小轮转：写满 `log_max_size_mb` 后执行 `.N-1 → .N … l4lb.log → .1`，再新建 `l4lb.log`。最多占用约 `(N+1) × size`。
- SIGHUP 时重新打开文件，以后可以改用系统 logrotate（配合 `postrotate kill -HUP`）。信号处理函数里只置一个原子标志，由写线程完成 reopen（1 秒内生效）。
- 启动时自动 `mkdir -p` 目录。目录或文件打不开时，打一条 WARN，退回 stderr 继续运行，不让日志问题挡住转发。
- 行格式保持不变，时间精确到毫秒：
  `[2026-10-02 10:00:00.123] [INFO ] [worker.cpp:258 worker_loop] Worker 1 started ...`

### 3. DPDK 日志并入同一个文件

用 `fopencookie` 创建一个 FILE，在 `rte_eal_init` 之前通过 `rte_openlog_stream()` 交给 DPDK。DPDK 每写一行，cookie 回调就把它送进同一个异步队列，级别由 `rte_log_cur_msg_loglevel()` 映射，行内标记 `[dpdk]`。

这样 EAL/驱动的报错（例如 vmxnet3 RSS 配置失败）也在 `l4lb.log` 里，跟着一起轮转，不需要单独的 `dpdk.log`。DPDK 的过滤级别仍由 EAL 的 `--log-level` 控制。

### 4. 配置

`[global]` 新增：

```ini
log_dir = /data/logs/l4     # 留空：只输出 stderr（旧行为，也是代码默认值）
log_max_size_mb = 100       # 1-10240
log_max_files = 5           # 1-100
log_stderr = on             # 同时输出到终端（前台调试用；后台运行可关闭）
```

命令行 `--log-dir <dir>` 覆盖配置，`--log-dir ""` 表示只输出 stderr。`config/lb.conf`、`config/lb_dr.conf`、`tests/perf/lab.conf` 默认写 `/data/logs/l4`。功能测试和单元测试不配置，行为不变。

### 5. 启动顺序

加载配置 → 设置级别 → 打开日志文件、接管 DPDK 日志 → 打印配置 → `rte_eal_init` …… → 退出统计 → `rte_eal_cleanup` → `Logger::shutdown()`。

配置文件本身的解析错误发生在知道 `log_dir` 之前，只会输出到 stderr。`--check-config` 不打开日志文件。

## 测试

- 单元测试 `tests/unit/test_logger.cpp`：
  - 多线程并发写，行数一致且每行完整
  - 小队列压满：写入行数 + 丢弃计数 = 总条数
  - 小文件轮转：文件个数不超过 N+1，内容不丢
  - SIGHUP reopen：把文件改名后请求 reopen，新日志写入新文件
- 功能测试（veth）：配置临时 `log_dir`，检查文件里有 `is running`、`[dpdk]` 行，退出后有 `Final Statistics`。

## 不做

- 统计行不拆分单独文件，仍在 `l4lb.log` 中（`grep` 统计行即可）。
- 不做崩溃时的 backtrace 落盘。进程段错误时，队列里最后约 1 秒的日志会丢，这是异步写的代价。需要的话可以后续加 SIGSEGV 处理。
