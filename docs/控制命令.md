# 控制命令

l4lb 运行时通过 Unix socket 接收命令，可以查询状态、增删后端、调整权重，不用重启。客户端是 `scripts/l4lbctl.py`。

## 一、连接方式

```bash
scripts/l4lbctl.py <命令> [参数...]            # 默认 socket /run/l4lb.sock
scripts/l4lbctl.py -s /tmp/x.sock <命令>       # 配置里 [control] socket 不是默认值时
scripts/l4lbctl.py help                        # 命令列表
```

- socket 路径由配置文件 `[control] socket` 指定，默认是 `/run/l4lb.sock`，权限 0600，只有 root 能连。
- 一次连接执行一条命令。成功返回 `ok`（或查询结果），失败返回以 `error:` 开头的说明，`l4lbctl.py` 此时的退出码是 1，方便在脚本里判断。
- 不用 Python 也可以：`echo services | sudo socat - UNIX-CONNECT:/run/l4lb.sock`。
- 命令修改的是运行时状态，**不会写回配置文件**。l4lb 重启后，后端恢复成配置文件里的样子。需要长期保留的改动，请同时改配置文件。

## 二、命令一览

| 命令 | 作用 |
|---|---|
| `services` | 列出服务和后端（RS），包括 id、权重、启用状态和健康状态 |
| `add <服务号> <ip:port[:weight]>` | 给服务添加后端，返回新 RS 的 id |
| `del <rs_id>` | 删除后端，它上面的已有连接会被断开 |
| `weight <rs_id> <权重>` | 修改权重（0~65535）；0 表示排空：不接新连接，已有连接继续 |
| `disable <rs_id>` / `enable <rs_id>` | 下线 / 上线后端；下线时已有连接也会被断开 |
| `stats` | 汇总计数：收发包数、转发数、会话数、丢包原因、网卡计数 |
| `stats -v` | 在 `stats` 基础上加上每个计数器和每个线程（receiver / worker / master）的数据 |
| `stats -r` | 按服务、按后端统计连接数、包数、字节数（类似 `ipvsadm -ln --stats`） |
| `rate` | 最近一个统计周期的速率（pps、bps、新建连接）和各线程忙碌率 |
| `counters` | 全部原始计数，一行一个 `key value`，给脚本用 |
| `delta ...` | 两次 `counters` 相减，算出这段时间的 PPS / bps（只在 `l4lbctl.py` 里，见第五节） |
| `log <debug\|info\|warn\|error>` | 修改日志级别 |
| `quit` | 停止 l4lb（等同于 Ctrl+C） |

## 三、后端管理

### 1. 查看服务和后端

```
$ scripts/l4lbctl.py services
mode fullnat  version 6
service 0 web 192.168.154.130:80/tcp sched wrr
  rs 3 192.168.154.140:80 weight 1 enabled up
  rs 4 192.168.154.140:8080 weight 1 enabled up
```

- `service 0`：服务号，`add` 命令要用。按配置文件里 `[service.*]` 出现的顺序从 0 开始编号。
- `rs 3`：后端 id，`del`、`weight`、`enable`、`disable` 要用。id 从 1 开始分配，删除后不复用，所以中间可能有空号。
- `enabled` / `disabled`：管理状态，由 `enable` / `disable` 命令控制。
- `up` / `down`：健康检查的结果。新加的后端默认是 `up`，健康检查连续失败 `failure_threshold` 次后才变成 `down`。
- `version`：每次修改加 1。

后端只有同时满足 `enabled`、`up`、权重大于 0 三个条件时，才会接新连接。

### 2. 添加后端

```bash
scripts/l4lbctl.py add 0 192.168.154.140:80        # 权重默认 1
scripts/l4lbctl.py add 0 192.168.154.140:8080:5    # 权重 5
```

返回 `ok rs <id>`。

- 地址必须是 `ip:port` 或 `ip:port:weight`，暂不支持主机名。
- 同一个服务里不能重复添加相同的 `ip:port`，会返回 `error: rs already exists (id N)`。
- 新后端的 MAC 通过 ARP 解析，不需要手动指定。master 线程每秒检查一次，解析完成前，发给它的新连接会被丢弃（计入 `drop_no_neigh`），一般 1 秒内就能就绪。
- 健康检查开启时，新后端会立即开始被探测。
- 每个服务最多 256 个后端，整个进程累计最多分配 16384 个 RS id。

### 3. 删除后端

```bash
scripts/l4lbctl.py del 1
```

删除后，它上面的已有连接在下一个包到达时被断开（TCP 回 RST 前的包会被丢弃，计入 `drop_rs_down`），新连接分给其余后端。

### 4. 平滑下线：先排空，再删除

```bash
scripts/l4lbctl.py weight 3 0      # 不再接新连接，已有连接继续
scripts/l4lbctl.py stats -r        # 观察 rs 3 的计数不再增长
scripts/l4lbctl.py del 3
```

### 5. 临时下线 / 恢复

```bash
scripts/l4lbctl.py disable 4       # 立即下线，已有连接也断开
scripts/l4lbctl.py enable 4
```

`disable` 只改管理状态，健康检查仍在继续。`enable` 之后，如果健康检查结果是 `down`，这个后端依然不会接流量。

### 6. 例：配置文件里的后端不可用，换成新的后端

现象：日志里出现 `No available backend for web`，`stats` 里 `drop_no_rs` 在增长。

```bash
$ scripts/l4lbctl.py services
service 0 web 192.168.154.130:80/tcp sched wrr
  rs 1 192.168.154.142:8081 weight 1 enabled down     # 健康检查失败
  rs 2 192.168.154.142:8082 weight 1 enabled down

$ scripts/l4lbctl.py add 0 192.168.154.140:80
ok rs 3
$ scripts/l4lbctl.py add 0 192.168.154.140:8080
ok rs 4
$ scripts/l4lbctl.py del 1
ok
$ scripts/l4lbctl.py del 2
ok
$ scripts/l4lbctl.py services
service 0 web 192.168.154.130:80/tcp sched wrr
  rs 3 192.168.154.140:80 weight 1 enabled up
  rs 4 192.168.154.140:8080 weight 1 enabled up
```

客户端执行 `curl http://192.168.154.130/` 就能看到 `rs 1`、`rs 2` 交替返回。下次重启前，记得把配置文件里的 `serverN` 也改掉。

### 7. 不支持的操作

- 增删服务（VIP:port）：只能改配置文件后重启。
- 修改后端的地址或端口：先 `add` 新的，再 `del` 旧的。
- 修改调度算法：只能改配置文件后重启。

## 四、状态查询

### `stats`：汇总

```
=== L4 LB Statistics (pipeline, workers: 3, steering: sw) ===
DPDK RX: 117, TX: 115, Dropped: 96
Forwarded: in 0, out 0, icmp err 0 | TCP 8, UDP 0, ICMP 88, ARP 21
Sessions: active 0, new 0, expired 0, closed 0
Redirect: out 0, in 0, rss mismatch 0, rss no hash 0 | neighbors 3
Drops: drop_no_session=88 drop_no_rs=8
NIC: ipackets 117, opackets 115, ibytes 9536, obytes 5976, imissed 0, ...
```

master 线程每隔 `stats_interval` 秒（默认 10 秒）也会把这些内容打到日志里，后面跟着 `Perf` 段（速率和忙碌率）。

常见丢包原因：

| 计数 | 含义 | 常见原因 |
|---|---|---|
| `drop_no_rs` | 新连接找不到可用后端 | 所有后端都 `down`、`disabled` 或权重为 0；用 `services` 查看 |
| `drop_no_session` | 非 SYN 包找不到会话 | 会话已超时或已关闭；发给 VIP 的 ICMP 差错找不到对应会话 |
| `drop_rs_down` | 会话所属的后端已经下线 | `del` / `disable` 后，已有连接的后续包 |
| `drop_no_neigh` | 下一跳 MAC 还没解析 | 新后端刚加入，ARP 还没回来 |
| `drop_no_service` | 发到本机地址但不是已配置的服务 | 端口或协议不对 |
| `drop_not_local` | 目的地址不是 VIP / LIP | 网卡收到了别的地址的包 |
| `drop_no_port` | FULLNAT 的 SNAT 端口用尽 | 短连接压测时 LIP 太少，在 `local_ips` 里多配几个 |
| `drop_table_full` | 会话表满 | 调大 `max_sessions` |
| `drop_rx_ring` / `rx_ring_full` | pipeline 下 worker 处理不过来 | worker 太少，或者 worker 被别的进程打扰 |
| `tx_full` | 网卡发送队列满 | 发送跟不上 |

### `stats -v`：按线程

在 `stats` 的基础上，再列出每一个计数器，以及每个线程一行：

```
receiver lcore 1 rx 422098 rx_ring_full 0 busy_ms 1084
worker 0 lcore 2 rx 0 ring_in 216127 tx 216118 redirect_out 0 ring_used 0 busy_ms 2442
worker 1 lcore 3 rx 0 ring_in 205971 tx 205962 redirect_out 0 ring_used 0 busy_ms 2361
master tx 45 tx_full 0
```

- `ring_in`：pipeline 模式下，worker 从 receiver 收到的包数。几个 worker 的数值应该差不多。
- `redirect_out`：转交给其他 worker 的包数，正常应接近 0。
- `busy_ms`：累计忙碌时间。两次查询相减再除以间隔，就是忙碌率（`rate` 命令已经算好了）。

### `stats -r`：按服务 / 后端

```
                                        conns     inpkts    inbytes    outpkts   outbytes
TCP 192.168.154.130:80 web                  4         24       1.8k         16       1.6k
  -> rs 3 192.168.154.140:80                3         18       1.3k         12       1.2k
  -> rs 4 192.168.154.140:8080              1          6        447          4        402
```

- `in`：客户端到后端方向，`out`：后端到客户端方向。DR 模式下回包不经过 LB，`out` 为 0。
- 都是从启动以来的累计值。已删除后端的计数不再显示。

### `rate`：最近一个周期

```
=== Perf (last 10.0s) ===
Rate: rx 39.6k pps 35.5 Mbps, tx 39.6k pps 34.5 Mbps, fwd in 20.0k pps, fwd out 19.6k pps, new sess 3.1k /s, drops 0 /s
Busy: receiver 10.8% | worker0 24.1% 20.2kpps | worker1 23.1% 19.5kpps
NIC: rx 39.6k pps, tx 39.6k pps, imissed +0, ierrors +0, rx_nombuf +0 (total imissed 0)
```

忙碌率只统计真正处理包的时间，不包括空轮询，所以能反映实际负载。`imissed` 增长说明网卡收包队列满了，receiver 收不过来。

## 五、压测时算 PPS：`counters` 和 `delta`

```bash
scripts/l4lbctl.py counters > /tmp/before.txt     # 压测前
# ... 在 client 上跑 wrk ...
scripts/l4lbctl.py delta /tmp/before.txt          # 压测后
```

其他用法：

```bash
scripts/l4lbctl.py delta a.txt b.txt              # 两个文件相减
scripts/l4lbctl.py delta --watch                  # 现在开始，Ctrl+C 结束
scripts/l4lbctl.py delta /tmp/before.txt --csv    # 一行 CSV；--csv-header 输出表头
```

报告里的 `total fwd` 就是 LB 的转发 PPS 和 bps：FULLNAT 下等于 `fwd in + fwd out`，DR 下只有 `fwd in`。详见 `docs/pps方案.md`。

`counters` 的 key 名字固定、值只增不减，第一行是纳秒时间戳 `time_ns`，适合自己写脚本解析。没有清零命令，需要区间值时用 `delta`。

## 六、常见问题

**`cannot connect to /run/l4lb.sock`**：l4lb 没在运行，或者配置里的 `[control] socket` 不是这个路径（用 `-s` 指定），或者没有用 root 运行。

**刚 `add` 的后端立刻变成 `down`**：健康检查从 `hc_src` 地址向后端发 TCP SYN。检查后端端口是否在监听、防火墙是否放行，以及后端能否路由回 `hc_src`（同一网段，或者网关能到达）。

**改了配置文件不生效**：配置文件只在启动时读取。运行中请用本文的命令，或者重启 l4lb。
