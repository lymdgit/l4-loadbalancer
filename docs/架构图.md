## 二、多核模型：无锁 per-worker 与分发

```mermaid
graph LR
    NICQ["NIC RX 队列（RSS/RETA）<br/>队列号 == worker 下标"]

    subgraph W0["worker 0（master，main lcore）"]
        R0["RX q0"] --> P0["process_packet"]
        P0 --> S0["会话表 #0<br/>hash + 数组 + 时间轮"]
        P0 --> T0["TX buffer → TX q0"]
        P0 --> M0["master 周期任务<br/>ARP / 邻居老化 / 健康检查 / 统计"]
    end

    subgraph W1["worker 1"]
        R1["RX q1"] --> P1["process_packet"]
        P1 --> S1["会话表 #1"]
        P1 --> T1["TX buffer → TX q1"]
    end

    subgraph WN["worker N"]
        RN["RX qN"] --> PN["process_packet"]
        PN --> SN["会话表 #N"]
        PN --> TN["TX buffer → TX qN"]
    end

    NICQ --> R0
    NICQ --> R1
    NICQ --> RN

    P0 -.->|"非本核的包<br/>redirect_ring（SPSC/MP）"| P1
    P1 -.->|redirect_ring| PN
    P0 -.->|"master_ring<br/>EV_ARP / EV_NEIGH_MISS / EV_HC_RESP"| M0

    SNAPX["Snapshot（只读，RCU 发布）"]
    SNAPX -.->|无锁读| P0
    SNAPX -.->|无锁读| P1
    SNAPX -.->|无锁读| PN

    NEIGHT["邻居表 / 路由<br/>rte_hash + RCU"]
    NEIGHT -.-> P0
    NEIGHT -.-> P1
    NEIGHT -.-> PN

    style SNAPX fill:#e8f0fe
    style NEIGHT fill:#e8f0fe
```

要点：

- **会话不共享**：每个 worker 独占自己的会话表，热路径无锁、无原子 RMW、无 malloc。
- **回程定位**：FULLNAT 选 SNAT 端口时用 `Steering::ret_owner()` 反算 RSS，保证回程包仍落到创建会话的核（不依赖 `rte_flow`，vmxnet3 可用）。
- **无 RSS 的网卡**：`init_sw()` 走 jhash 软件分发，落到别的核的包经 `redirect_ring` 转交（只转交一次）。
- **FULLNAT 端口分配**：`port_step` 让端口按核错开，避免多核对同一 LIP 端口段竞争。

## 四、控制面：配置快照与健康检查

```mermaid
graph LR
    USER["运维 / scripts/l4lbctl.py<br/>stats / services / weight / enable / add / del"]
    SOCK["unix socket /run/l4lb.sock（0600）"]
    CTLT["ctrl/control.cpp 控制线程"]
    MGR["SnapshotManager<br/>期望状态（加锁修改）"]
    PUB["build() → 新 Snapshot → 原子替换<br/>rte_rcu_qsbr_synchronize() 后释放旧快照"]
    CUR["g_dp.snapshots.current()"]
    WKS["各 worker 数据面<br/>每轮 rte_rcu_qsbr_quiescent()"]

    USER --> SOCK --> CTLT
    CTLT -->|"set_weight / set_enabled / add_rs / del_rs"| MGR
    MGR --> PUB --> CUR
    CUR -.->|"acquire 读，无锁"| WKS
    WKS -.->|报告静默期，允许回收旧快照| PUB

    HCT["HealthChecker（master 内）"]
    HR["health_ring：HealthEvent"]
    HCT -->|"TCP 探测回包经 master_ring 汇总"| HR
    HR --> CTLT
    CTLT -->|set_health| MGR

    style PUB fill:#e8f0fe
    style CUR fill:#e8f0fe
```

健康检查在**数据面内**完成：master 用 `hc_src` + 专用端口段发 TCP 探测，回包由任意 worker 识别后经 `master_ring` 回传给 master 判定，结果通过 `health_ring` 交给控制线程写入快照。

## 六、启动与运行时序

```mermaid
sequenceDiagram
    participant M as main.cpp
    participant EAL as DPDK EAL
    participant P as port/steering
    participant G as 全局资源<br/>RCU/route/neigh/rings/snapshot
    participant W as worker 0..N
    participant C as 控制线程

    M->>M: 解析参数 + 加载 lb.conf（--check-config 可只校验）
    M->>EAL: rte_eal_init
    M->>M: 创建 mbuf pool
    M->>P: port_init（队列数、RSS/RETA、offload、MTU）
    M->>G: RCU init、route init、neigh init（静态 MAC 入表）
    M->>G: master_ring / health_ring / SnapshotManager.init
    M->>W: 为每个 lcore 分配 WorkerCtx + 会话表 + redirect_ring
    M->>C: ControlServer.start（unix socket）
    M->>W: rte_eal_remote_launch(worker_loop) × N，main lcore 作为 worker 0
    loop 每轮循环
        W->>W: rx_burst → process_packet → tx_burst（热路径）
        W->>W: RCU quiescent
        W->>W: 每 1024 轮：推进时间轮、会话过期、master 周期任务
    end
    C-->>G: 控制命令 → 构建并发布新快照
    M->>W: 收到信号 → g_running=false → 退出并打印统计
```
