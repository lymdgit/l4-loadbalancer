# 校验和处理原理与实例分析

本文档结合本项目代码，讲解 FULLNAT 改写地址和端口时如何更新校验和（Checksum）。第 1～4 节、第 6 节是原理，第 5 节是本项目实际采用的策略（硬件 offload、全量计算、增量更新三条路径）。

## 1. 核心原理：增量更新 (Incremental Update)

在高性能网络转发中，如果每次修改数据包都重新计算整个包的校验和（全量计算），需要读取所有数据，效率极低。
RFC 1624 定义了增量更新公式，可以在不读取数据载荷的情况下，仅根据**修改前后的差值**更新校验和：

```
HC' = ~(~HC + ~m + m')
```
*   `HC` : 旧的校验和 (Old Checksum)
*   `HC'` : 新的校验和 (New Checksum)
*   `m`  : 旧的字段值 (Old Value)
*   `m'` : 新的字段值 (New Value)

这个算法实现在 `include/protocol/checksum.h` 的 `L4Checksum::incremental_update`（以及 `update_tcp_checksum_ip/port`、`update_udp_checksum_ip/port`）；全量计算在 `src/protocol/checksum.cpp`。

## 2. 实例场景：入站流量 (DNAT)

假设通过负载均衡器转发一个 TCP SYN 包：
*   **客户端 (Client)**: 1.1.1.1
*   **VIP**: 2.2.2.2 (端口 80)
*   **后端真实服务器 (RS)**: 192.168.1.10 (端口 8080)

**动作**：LB 将目的 IP 从 `2.2.2.2` 改为 `192.168.1.10`，将目的端口从 `80` 改为 `8080`。

### 涉及的代码函数

改写入口是 `nat_rewrite()`（`src/forward/nat_forwarder.cpp`），由 `src/core/processor.cpp` 的入站和回程处理调用。FULLNAT 会同时改源地址、目的地址、源端口、目的端口四个字段，这里为了讲清楚原理，只看目的地址和目的端口。软件增量路径的代码（简化）：

```cpp
// nat_rewrite()，网卡不支持 L4 校验和 offload、且 TCP 选项没有变化时
ip->src_ip = rw.src_ip;
ip->dst_ip = rw.dst_ip;
--ip->ttl;
ip_checksum(ip);                       // IP 头校验和：直接全量重算（只有 20 字节）

tcp->src_port = rw.src_port;
tcp->dst_port = rw.dst_port;
// TCP 校验和：伪头部里的两个 IP、TCP 头里的两个端口，各做一次增量更新
L4Checksum::update_tcp_checksum_ip(tcp, old_src, rw.src_ip);
L4Checksum::update_tcp_checksum_ip(tcp, old_dst, rw.dst_ip);
L4Checksum::update_tcp_checksum_port(tcp, old_sp, rw.src_port);
L4Checksum::update_tcp_checksum_port(tcp, old_dp, rw.dst_port);
```

## 3. 计算过程详解

为了“琢磨”，我们用具体的 16 进制数字来模拟算一下。

### 3.1 准备数据
*   **旧 IP (VIP)**: 2.2.2.2  => `0x02020202`
    *   高16位: `0x0202`
    *   低16位: `0x0202`
*   **新 IP (RS)**: 192.168.1.10 => `C0.A8.01.0A` => `0xC0A8010A`
    *   高16位: `0xC0A8`
    *   低16位: `0x010A`
*   **旧端口 (80)**: `0x0050`
*   **新端口 (8080)**: `0x1F90`

假设 **原始 IP 校验和** 为 `0xABCD`。
假设 **原始 TCP 校验和** 为 `0x1234`。

---

### 3.2 步骤一：更新 IP 校验和
IP 头部校验和只保护 IP 头部。我们修改了 `dst_ip`（32位，分为两个16位）。

> 本项目对 IP 头校验和直接全量重算（`nat_forwarder.cpp` 中的 `ip_checksum()`）：IP 头只有 20 字节，同时改了两个地址和 TTL，全量算比多次增量更简单，开销也可以忽略。下面的增量算法作为原理说明。

增量写法：
```cpp
ip->checksum = L4Checksum::incremental_update(ip->checksum, old_dst_ip >> 16, new_dst_ip >> 16);
ip->checksum = L4Checksum::incremental_update(ip->checksum, old_dst_ip & 0xFFFF, new_dst_ip & 0xFFFF);
```

**计算逻辑 (简化版)**:
1.  **第一次更新 (高16位)**:
    *   差值 = `new_val` - `old_val` = `0xC0A8` - `0x0202` = `0xBEA6`
    *   新校验和 ~= 旧校验和 - 差值 (注意这是反码运算的直观理解，实际通过反码加法实现)
    *   你的 `incremental_update` 函数内部执行的是 `~(~old_sum + ~old_val + new_val)`。

2.  **第二次更新 (低16位)**:
    *   同理处理 `0x010A` 和 `0x0202` 的差值。

这样，**不需要**读取 IP 头部的其他字段（如 TTL、Protocol、SrcIP），就能得到正确的新 IP 校验和。

---

### 3.3 步骤二：更新 TCP 校验和 (最复杂的部分)
TCP 校验和包含三部分内容：**TCP伪头部 (Pseudo Header)** + **TCP头部** + **TCP数据**。

#### A. 伪头部变更 (IP 变了)
虽然 IP 地址不在 TCP 头部里，但在 TCP 校验和计算中包含在“伪头部”里。所以 IP 变了，TCP 校验和必须变！

代码调用：
```cpp
L4Checksum::update_tcp_checksum_ip(tcp, old_dst_ip, new_dst_ip);
```
它只更新 TCP 校验和（因为伪头部里的 IP 变了），IP 头校验和另行处理。逻辑与上面完全一样，计算 IP 的增量差值。

#### B. 端口变更
我们将端口从 80 改为 8080。

代码调用：
```cpp
L4Checksum::update_tcp_checksum_port(tcp, old_port, new_port);
```
*   `old_port` = `0x0050`
*   `new_port` = `0x1F90`
*   将这个差值再次叠加到 TCP 校验和上。

## 4. 为什么增量更新高效？

### 传统低效做法
```cpp
// 1. 修改字段
ip->dst_ip = new_ip;
// 2. 重新计算 IP 校验和 (需要读取 20 字节)
ip->checksum = calculate_ip_checksum(ip);
// 3. 重新计算 TCP 校验和 (需要读取 IP伪头 + TCP头 + TCP所有数据Payload)
// 如果 payload 有 1500 字节，这里就要读 1500 字节！
tcp->checksum = calculate_tcp_checksum(ip, tcp);
```

### 增量更新做法 (O(1) 复杂度)
```cpp
// 只做几次 16 位整数的加减法，耗时只需几纳秒
update(sum, old_ip_high, new_ip_high);
update(sum, old_ip_low, new_ip_low);
update(sum, old_port, new_port);
```
无论数据包有多大，增量更新的耗时都是恒定的。这也是高性能转发普遍采用增量更新的原因。

## 5. 本项目的实际策略

`nat_rewrite()` 根据网卡能力和是否改了 TCP 选项，选择三条路径之一：

| 条件 | L4 校验和怎么算 | 代码 |
| :--- | :--- | :--- |
| 编译时 `L4LB_HW_CKSUM=ON`（默认）且网卡支持 TCP/UDP TX 校验和 offload | 软件只把伪头部校验和（`rte_ipv4_phdr_cksum`）写进校验和字段，设置 `l2_len/l3_len/l4_len` 和 `RTE_MBUF_F_TX_TCP_CKSUM`（或 UDP），由网卡算完剩下的部分 | `l4_checksum_full()` 的硬件分支 |
| 插入了 TOA，或去掉了 SYN 的 timestamp（TCP 头内容和长度都变了，增量更新不再适用），且网卡不支持 offload | 软件全量重算（伪头部 + TCP 头 + 载荷） | `l4_checksum_full()` 的软件分支，`L4Checksum::recalculate_tcp_checksum` |
| 网卡不支持 offload，TCP 选项没变 | 增量更新：两个 IP 地址 + 两个端口，共四次 | `update_tcp_checksum_ip/port` |

其他细节：
- **IP 头校验和**：始终在软件里全量重算（20 字节），不使用 offload。
- **网卡支持哪些 offload**：`port_init()` 用 `期望的 offload & 网卡能力` 得到实际启用的 TX offload（`src/dataplane/port.cpp`），启动日志里会打印 `TX offloads 0x...`。本机 vmxnet3 是 `0xc`（TCP + UDP 校验和）。
- **UDP**：原来的校验和为 0 表示"不校验"，改写后保持为 0；增量更新的结果如果恰好是 0，写成 `0xFFFF`（UDP 里 0 有特殊含义）。
- **DR 模式**只改 MAC 地址，IP 和 L4 都不变，不需要更新任何校验和。
- **收包方向**：端口开启了 `RTE_ETH_RX_OFFLOAD_CHECKSUM`，网卡标记为校验和错误的包在 `processor.cpp` 的 `cksum_bad()` 处直接丢弃，计入 `drop_cksum`。
- **ICMP 差错报文转换**（`nat_rewrite_icmp_error()`）：内层被引用报文的 IP 头校验和、外层 IP 头校验和、整个 ICMP 校验和都全量重算；内层的 L4 校验和覆盖整个原始报文，而 ICMP 里只带了前 8 字节，无法重算，保持不变（接收方协议栈不校验内层 L4 校验和）。

## 6. 什么是伪头部 (Pseudo Header)？

这是一个初学者非常容易困惑的概念。

### 6.1 定义
**伪头部**（Pseudo Header）不是一个真实存在于数据包里的物理头部（你在 Wireshark 或者内存里是找不到这 12 个字节的）。它是一个**虚拟的数据结构**，仅在计算 TCP 或 UDP 校验和的那一瞬间被“假想”出来，参与计算。

### 6.2 包含内容 (12字节)
1.  **源 IP 地址** (4字节)
2.  **目的 IP 地址** (4字节)
3.  **保留位** (1字节，全0)
4.  **协议号** (1字节，TCP=6, UDP=17)
5.  **TCP/UDP 长度** (2字节)

### 6.3 为什么要设计它？
**为了防止路由错误。**

TCP 本身只存在于 IP 的载荷（Payload）中。如果只对 TCP 头部和数据做校验，会发生什么？
*   假设路由器出错，把发给 A 的包发给了 B。
*   B 收到包，解开 IP 头，拿出 TCP 段。
*   如果 TCP 校验和**不包含**目的 IP，那么 B 校验 TCP 发现是正确的，就会错误地把数据交给 B 上的应用程序。

通过把 IP 地址加入 TCP 校验和：
*   校验和就绑定了 `<源IP, 目的IP, 端口>`。
*   如果包被错误地投递到了错误的 IP，接收端在计算校验和时，会使用**它自己的 IP**（作为目的 IP）来算。
*   结果发现校验和对不上（因为发送端是用**原来的目的 IP**算的），从而丢弃该包。

这就是为什么**修改了 IP 地址，必须更新 TCP 校验和**的原因——因为 IP 也是 TCP 完整性保护的一部分。
